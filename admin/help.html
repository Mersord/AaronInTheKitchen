Sign in

Open the editor and choose GitHub sign-in. Use the GitHub account that accepted the repository invitation. Allow the sign-in popup and authorize the recipe editor. Ask Lukas to check access if your account is rejected.

Edit an existing recipe

Choose Recipes and select the recipe. Existing ingredient lists and instructions are in formatted text fields. Expand an ingredient group or cooking step, edit its text, and use the toolbar for bold text, lists and links.

The hidden internal section identifiers preserve the original recipe structure. You never need to change those. A recipe's existing address is retained when you change its title.

Create a new recipe

Choose New Recipe, enter the title and category, and add ingredients and cooking steps. An introduction, photo, YouTube video, servings and times are optional. Lower display-order numbers appear earlier in the directories.

Add groups such as Cake, Filling or Frosting. For an ingredient, use either the formatted list or a measured ingredient row — not both, or it will appear twice.

Leave the amount empty for “to taste” or an unspecified amount. Ingredient groups normally use Display after step: 0, which puts them above the instructions. A nonzero value puts a later frosting or topping list after that cooking step, preserving the placement of some imported recipes.

Measurements

Use metric as the source. In instructions, write recognisable quantities such as 250 g, 150 mL, 20 cm and 180 °C. The build makes the Metric/US versions. Copy the degree sign from this example when entering a temperature.

Grams normally convert to ounces or pounds. A cup of flour is not the same weight as a cup of another ingredient. Only enter Grams per US cup when you know the ingredient-specific value, or use the optional tested US-display override.

Review both unit views on the published recipe after changing quantities. Editing an imported formatted block recalculates its conversions and may change a previous cup label to ounces. Use measured rows with a verified cup weight to keep a specific cup equivalent. Unchanged imported blocks retain their original unit pairs.

Photos and YouTube

Upload a reasonably sized recipe photo in the picture field and give it a useful description. Leaving it empty uses a placeholder on recipe cards. Paste the YouTube video link into the video field; no embed code or video upload is needed. The published page uses the existing video player and preview.

The editor preview shows content and pictures, not a live YouTube player or working unit switch. Those features run on the built public page.

Save and publish

Use Decap's publish action to save changes in GitHub. Visible on website determines whether the next build includes the recipe. Turn it on when the recipe is ready, publish, then allow the website's GitHub publishing workflow to finish. Check the result on the public website.

To take a recipe off the website, switch visibility off and publish again. The delete button is disabled to reduce accidental data loss.

Hidden does not mean private. Recipes saved in a public repository can still be read on GitHub, including previous revisions. Do not put personal or confidential information in recipe fields.

When something does not update

Wait for the publishing workflow to finish, then refresh the public page. A rejected build leaves the previous public version in place. Ask Lukas to check the latest GitHub Actions result instead of repeatedly publishing. Do not replace the repository with an old website ZIP.

Sign out when using a shared computer. Only trust the editor on the website address Lukas gave you; do not provide GitHub credentials to an imitation login form.
